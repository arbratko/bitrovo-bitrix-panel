# Установка Bitrovo: Bitrix Panel

## Системные требования

- поддерживаемая ОС из [SUPPORTED-OS.md](SUPPORTED-OS.md);
- systemd;
- публичный статический IPv4;
- свободный локальный порт `3847`;
- доступный внешний порт `80` (нужен для ACME-проверки сертификата);
- root-доступ по SSH.

Установщик не создаёт `default_server` и не заменяет конфигурации существующих
сайтов. Для Bitrovo создаётся отдельный nginx virtual host с точным
`server_name`, равным IP сервера.

Если порт `443` уже занят другим сайтом с `default_server` (например,
BitrixVM), Bitrovo автоматически размещается на отдельном HTTPS-порту
(по умолчанию `9443`), который открывается в firewall. Порт можно задать
вручную переменной `PANEL_HTTPS_PORT`.

## Установка одной командой

Безопасный вариант сначала полностью скачивает bootstrap и только затем
запускает его:

```bash
curl -fsSL https://cdn.bitrovo.ru/bitrovo-bitrix-panel/install.sh \
  -o /tmp/bitrovo-panel-install.sh \
  && sudo bash /tmp/bitrovo-panel-install.sh --full --yes
```

Bootstrap проверяет цифровую подпись release manifest, SHA-256 архива,
архитектуру и операционную систему. Неподписанный или повреждённый архив не
запускается.

Режим `--full` устанавливает только **отсутствующие** компоненты: зависимости
Bitrovo и, при необходимости, базовый стек Битрикс (MariaDB, PHP-FPM). Уже
установленные пакеты и службы не переустанавливаются и не обновляются.
Режим `--panel-only` ничего не устанавливает через пакетный менеджер и
останавливается, если обязательных компонентов нет.

Для предварительной проверки **без изменений на сервере** (скачивание + dry-run
одной командой — файл в `/tmp` сам по себе не появляется):

```bash
curl -fsSL https://cdn.bitrovo.ru/bitrovo-bitrix-panel/install.sh \
  -o /tmp/bitrovo-panel-install.sh \
  && sudo bash /tmp/bitrovo-panel-install.sh --panel-only --dry-run
```

## Что происходит при установке

Установка занимает несколько минут. В консоли может быть много текста — это
нормально: часть вывода генерирует сама операционная система (apt, dnf,
needrestart), а не Bitrovo. Строки установщика всегда начинаются с
`[bitrovo-panel]`.

### Шаг за шагом

| Этап | Что делает установщик | Изменяет ли ваши сайты |
| --- | --- | --- |
| 1. Проверка подписи | Скачивает manifest и архив с CDN, проверяет цифровую подпись Ed25519 и SHA-256. При несовпадении — **остановка до любых изменений** | Нет |
| 2. Preflight | Определяет ОС, архитектуру, свободное место, занятость портов. При нарушении условий — **остановка до любых изменений** | Нет |
| 3. Зависимости Bitrovo | Проверяет наличие nginx, python3, curl и др. **Ставит только то, чего нет.** Уже установленное не трогает | Нет |
| 4. Стек Битрикс | MariaDB и PHP-FPM — **только если полностью отсутствуют.** Если на сервере уже есть MySQL, MariaDB, Percona или PHP — шаг пропускается | Нет |
| 5. Файлы Bitrovo | Распаковывает Bitrovo в `/opt/bitrovo-panel`, настройки — в `/etc/bitrovo-panel`. Отдельно от сайтов | Нет |
| 6. Nginx | Добавляет **один свой** конфиг с `server_name`, равным IP сервера. **Не редактирует** конфиги существующих сайтов. Перед reload — `nginx -t`; при ошибке — откат | Нет |
| 7. HTTPS | Выпускает IP-сертификат Let's Encrypt (или самоподписанный, если ACME недоступен). Настраивает systemd timer для продления | Нет |
| 8. Health-check | Проверяет, что API и HTTPS отвечают. При ошибке — **полный откат** всех внесённых изменений | Нет |

### Результат установки

Bitrovo открывается по адресу из конца установки (см. раздел «Результат» ниже).
В терминале выводится одноразовый bootstrap-токен для создания
администратора.

## Безопасность на сервере с сайтами

**Главное:** установщик **не выполняет** `apt upgrade`, `dnf upgrade` и не
обновляет систему целиком. Он **не переустанавливает** уже установленные
пакеты и **не меняет** конфигурации ваших сайтов, баз данных и веб-сервера.

### Что установщик никогда не делает

- не обновляет все пакеты ОС;
- не заменяет уже работающий nginx, PHP, MySQL/MariaDB;
- не правит `nginx.conf`, vhost'ы и конфиги существующих сайтов;
- не удаляет и не перезаписывает данные сайтов и баз;
- не создаёт `default_server` на порту 443 — ваш основной сайт остаётся
  default, если он им был.

### Что может произойти на «пустом» сервере

Если на VPS ещё нет nginx, Python или других зависимостей, установщик
**доустановит только недостающее** через штатный пакетный менеджер (apt/dnf).
Иногда apt при установке одного пакета подтягивает security-обновления его
зависимостей — это штатное поведение Ubuntu/Debian, то же самое делает
`unattended-upgrades` каждую ночь. Установщик **не инициирует** такие
обновления, если пакеты уже стоят.

На **уже настроенном** сервере (BitrixVM, рабочий VPS с сайтами), где nginx,
PHP и СУБД уже установлены, шаги 3 и 4 проходят **вхолостую** — Bitrovo
ставится рядом, не затрагивая окружение сайтов.

### Порт 443 и BitrixVM

Если порт 443 уже занят вашим сайтом (типично для BitrixVM), Bitrovo
автоматически размещается на отдельном HTTPS-порту (по умолчанию **9443**)
и открывает его в firewall. Ваш сайт на 443 не затрагивается. Точный адрес
выводится в конце установки.

### Откат при ошибке

Установка **транзакционная**: при любой ошибке на шагах 5–8 установщик
возвращает nginx, systemd и каталоги к состоянию до начала установки.
Поломанный «полу-установленный» сервер не остаётся.

### Кратко для сравнения

| Ситуация | Поведение установщика |
| --- | --- |
| Чистый VPS, нет nginx/PHP/СУБД | Доустанавливает недостающее + Bitrovo |
| Сервер с сайтами, всё уже стоит | Только Bitrovo, пакеты не трогает |
| BitrixVM, 443 занят | Bitrovo на 9443, Bitrix на 443 без изменений |
| Ошибка на любом шаге | Откат, сайты не пострадали |

## Результат

Bitrovo открывается по адресу:

```text
https://PUBLIC_IP/panel/
```

(или `https://PUBLIC_IP:9443/panel/`, если порт 443 занят другим сайтом —
точный адрес выводится в конце установки).

Покупать или подключать домен не требуется. Установщик получает бесплатный
короткоживущий IP-сертификат Let's Encrypt и создаёт systemd timer для его
регулярного продления.

Для IP-сертификата Let's Encrypt требуется Python 3.10+ (на RHEL-семействе
установщик сам ставит `python3.12`). Если выпуск сертификата невозможен,
Bitrovo запускается на самоподписанном сертификате: соединение шифруется,
но браузер покажет предупреждение.

API слушает только `127.0.0.1:3847`. Браузер обращается к
`https://PUBLIC_IP/panel/api/...`, а nginx безопасно передаёт запрос внутреннему
API.

## Первый вход после установки

Готового логина и пароля **нет** — их вы задаёте сами при первом запуске.
Bootstrap-токен из терминала — **не пароль**, а одноразовый ключ, который
подтверждает, что создавать администратора может только тот, у кого есть
доступ к серверу.

### Шаг 1. Откройте Bitrovo в браузере

Используйте **точный адрес из конца установки**, например:

```text
https://46.173.17.199:9443/panel/
```

Если порт 443 занят BitrixVM или другим сайтом, Bitrovo будет на **9443**.
На чистом VPS без других сайтов — обычно `https://PUBLIC_IP/panel/` без порта.

Nginx автоматически перенаправляет типичные ошибки в адресе:

| Вы открыли | Что произойдёт |
| --- | --- |
| `http://IP/panel/` | редирект на `https://IP:9443/panel/` (если Bitrovo на 9443) |
| `http://IP:9443/panel/` | редирект на `https://IP:9443/panel/` |

> **Ограничение BitrixVM:** адрес `https://IP/panel/` (порт 443 без указания
> `:9443`) спасти нельзя — браузеры не передают SNI при обращении по IP,
> поэтому запрос попадает в vhost Bitrix с его самоподписанным сертификатом.
> Используйте полный URL с портом `:9443`. На чистом сервере без BitrixVM
> Bitrovo работает на 443 и таких проблем нет.

Точный URL всегда можно посмотреть:

```bash
grep publicUrl /etc/bitrovo-panel/install-manifest.json
```

### Шаг 2. Создайте администратора

На экране **«Первый запуск»** заполните:

| Поле | Что ввести |
| --- | --- |
| **Логин** | Придумайте сами, минимум 4 символа (например `admin`) |
| **Пароль** | Придумайте сами, минимум 12 символов |
| **Токен первичной настройки** | Строка из терминала после установки |

Нажмите «Создать администратора».

### Шаг 3. Дальнейший вход

После создания администратора форма с токеном исчезает. Входите обычным
**логином и паролем**, которые задали на шаге 2.

### Если токен потеряли

Пока администратор не создан, токен хранится на сервере:

```bash
grep PANEL_BOOTSTRAP_TOKEN /etc/bitrovo-panel/config.env
```

### Если забыли пароль администратора

Через браузер восстановить пароль нельзя. Нужен root на сервере.
Команда доступна с версии **1.0.128** — сначала обновите панель, затем:

```bash
/opt/bitrovo-panel/current/scripts/reset-admin.sh
```

Полный путь не зависит от PATH. После обновления также работает короткое имя
`bitrovo-panel-reset-admin` (симлинк в `/usr/sbin`).

Что делает команда:

1. останавливает службу панели;
2. делает резервную копию `panel.json`;
3. **сбрасывает пароль существующего пользователя** (логин сохраняется;
   второго администратора не создаёт);
4. сбрасывает сессии и блокировки входа по IP;
5. снова запускает панель.

Сайты, базы и настройки не трогает. Если пользователей несколько:

```bash
/opt/bitrovo-panel/current/scripts/reset-admin.sh --username=admin
```

Если пользователей ещё нет — создаст первого администратора.

Подробнее — в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Структура установки

```text
/opt/bitrovo-panel/
  current
  previous
  releases/<version>
  shared/data
  shared/logs
  shared/backups

/etc/bitrovo-panel/
  config.env
  install-manifest.json
```

Основной API работает от непривилегированного пользователя `bitrovo-panel`.
Команды и полный файловый менеджер выполняются отдельным root-helper через
Unix socket, который не открыт в сеть.

## Обновление

От root:

```bash
bitrovo-panel-update
```

То же самое полным путём:

```bash
/opt/bitrovo-panel/current/scripts/update.sh
```

Выбор beta-канала:

```bash
BITROVO_CHANNEL=beta bitrovo-panel-update
```

Перед обновлением проверяются активные задачи и создаётся backup данных.
Новая версия проходит health-check. При ошибке установщик возвращает предыдущую
конфигурацию.

Ручной откат:

```bash
bitrovo-panel-update --rollback
```

## Удаление

Обычное удаление сохраняет данные и резервные копии:

```bash
bitrovo-panel-uninstall
```

То же самое полным путём:

```bash
/opt/bitrovo-panel/current/scripts/uninstall.sh
```

Безвозвратное удаление данных выполняется только явным флагом:

```bash
bitrovo-panel-uninstall --purge-data
```

Сайты, базы данных и конфигурации сайтов этим сценарием не удаляются.
