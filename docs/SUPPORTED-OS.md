# Поддерживаемые операционные системы

## Проверенная матрица

Полный цикл `install → update → rollback → uninstall` проверен на реальной
VPS с BitrixVM (CentOS Stream 9); установка, работа служб, HTTPS и удаление
дополнительно проверены в systemd-окружениях остальных систем:

| Система | Статус |
| --- | --- |
| Debian 11 | проверено (OpenSSL 1.1.1, как Ubuntu 20.04) |
| Debian 12 | проверено |
| Debian 13 | проверено |
| Ubuntu 20.04 LTS | проверено (OpenSSL 1.1.1; Let's Encrypt по IP — только при Python >= 3.10) |
| Ubuntu 22.04 LTS | проверено |
| Ubuntu 24.04 LTS | проверено |
| Ubuntu 26.04 LTS | проверено |
| CentOS Stream 9 (включая BitrixVM 9) | проверено, полный цикл на VPS |
| CentOS Stream 10 | проверено |
| AlmaLinux 9 | проверено |
| Rocky Linux 9 | проверено |
| AlmaLinux 10 / Rocky 10 / RHEL 9-10 | адаптер готов, ожидает проверки |

Полная установка с CDN одной командой дополнительно прогнана 2026-07-18 на
systemd-контейнерах всех перечисленных «проверенных» систем: панель ставится,
службы активны, HTTPS отвечает.

Ubuntu 18.04 не поддерживается: встроенному Node.js 24 требуется glibc >= 2.28,
а в Ubuntu 18.04 — glibc 2.27; сама система снята с поддержки в 2023 году.

Все системы: `x86_64`, systemd. Поддержка `arm64` будет включена после
отдельной сборки runtime и полного набора тестов.

## BitrixVM и «рабочие» серверы

Панель ставится рядом с существующими сайтами, ничего не заменяя:

- уже занятые порты 80/443 (BitrixVM, любой рабочий сервер) — панель
  автоматически уходит на отдельный HTTPS-порт и открывает его в firewall;
- кастомный `nginx.conf` BitrixVM без `conf.d` — установщик подключает
  собственный каталог конфигураций с проверкой `nginx -t` и откатом;
- firewalld (RHEL) и ufw (Debian/Ubuntu) поддерживаются;
- ставятся только отсутствующие зависимости, существующие пакеты
  не заменяются (включая `curl-minimal` на RHEL 9).

## Особенности установки рядом с другими сайтами

- Если порт 443 уже занят другим сайтом (например, BitrixVM), установщик
  автоматически размещает панель на отдельном HTTPS-порту (по умолчанию 9443)
  и открывает его в firewall (firewalld или ufw). Порт можно задать вручную:
  `PANEL_HTTPS_PORT=<порт>`.
- Конфигурация nginx подключается только через каталоги, которые уже
  включены в `nginx.conf`; если стандартный `conf.d` не подключён,
  установщик безопасно добавляет собственный include с проверкой `nginx -t`
  и откатом.

## Неподдерживаемые системы

Установщик должен завершаться до любых изменений на:

- CentOS Linux 7/8, снятых с поддержки;
- системах без systemd;
- Alpine Linux;
- Arch Linux;
- openSUSE;
- неизвестных дистрибутивах и архитектурах.

Ручной запуск на неподдерживаемой системе не означает официальную поддержку.

## Требования к серверу

- публичный статический IPv4 для основного сценария HTTPS по IP;
- доступный порт 80 для ACME-проверки (сертификат Let's Encrypt на IP);
- порт 443 или свободный альтернативный HTTPS-порт для панели;
- SSH-доступ администратора;
- Python 3.10+ для выпуска IP-сертификата Let's Encrypt (иначе панель
  временно работает на самоподписанном сертификате);
- достаточное место для текущего и предыдущего release, данных и backup;
- отсутствие блокировки доступа к официальному CDN и ACME-сервису.

Установщик обязан выполнить preflight и ничего не менять, если обязательные
условия не соблюдены.
